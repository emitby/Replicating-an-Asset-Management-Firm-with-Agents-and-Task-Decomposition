# Guardrail engineering: what each guardrail protects

A guardrail here is a rule **enforced by code** that an agent cannot talk its way past. Prompts *describe* every rule so agents comply on the first try, but compliance never depends on the prompt. This page lists, for each guardrail:

- the **harm** it prevents
- **where** it's enforced
- **how** it works
- **what tests it**
- its **known limits**

## Design principles

1. **Agents decide, code computes.** Agents choose which tools to call and write prose. Every number, table, disclosure and trading rule is computed by deterministic Python. An agent cannot produce a return figure. It can only quote one.
2. **Enforce at the earliest point, re-check later (defense in depth).** Most rules are checked at **four** layers:
   - **Tool time:** the agent gets an `is_error` result and rewrites.
   - **Hand-off:** the harness validator re-checks before the next stage starts.
   - **Eval:** scorers re-check the saved artifacts and the final PDF text.
   - **Red-team:** adversarial inputs test the guardrail itself.
3. **Errors are instructions.** Every rejection names the exact violation and the fix, such as "Numbers not found in the computed results: ['14.2%']. Use only values from the tools…". Most agent self-corrections in the traces come from these messages.
4. **Compliance content is owned by code.** Text that must be present (disclosures, labels, footers) is generated by code, never requested from an agent.
5. **Every guardrail must be recoverable.** A check that rejects valid text, with no way to fix it, strands the agent. See the v3 lessons below.

## Threat model

| # | Harm | Example | Who suffers |
|---|---|---|---|
| H1 | Fabricated or distorted performance figures | "compounds at 14.2%" when the computed CAGR is 9.1% | Investors, and the firm's regulatory standing |
| H2 | Promissory or misleading marketing language | "guaranteed", "will outperform", "act now" | Investors |
| H3 | Cherry-picking: showing only good windows | Leading with drawdown protection when the 5Y drawdown was worse than SPY's | Investors |
| H4 | Claims about a mechanism the strategy doesn't have | Pitching always-invested momentum as "designed to limit drawdowns" | Investors |
| H5 | Missing or wrong disclosures | Hypothetical results shown as real; a gross return shown as net | Investors and the firm |
| H6 | Impersonation and false credentials | A persona "formerly at Morgan Stanley", "Warren Buffett", a made-up certification | Real people and firms, and investors |
| H7 | Look-ahead and backtest bias | A signal using tomorrow's price; picking the MA with hindsight | Every number downstream |
| H8 | Agents touching the host system | Writing outside the project, deleting files, reading OS configuration | The user's machine (CLAUDE.md) |
| H9 | Runaway cost or loops | An agent looping on a failing tool | The user's API bill |
| H10 | Data errors | Today's partial session treated as a close; a split shown as a 50% crash | Every number downstream |

## The guardrails

### G1. Numeric faithfulness (protects against H1)

**Where:** `strategy/guardrails.py`, called by `save_analytics`, `add_slide` and `revise_slide` (tool time), by `validate_presentation` (hand-off), by `narrative_faithfulness` (eval), and by the red-team.

**How:**
- `extract_numbers` finds every number in agent prose, with its precision and unit. Dates (ISO, written and slash forms) are removed first. Calendar years (1990–2100, no decimals, no unit) are skipped. A number glued to letters (`MA200`, `Q3`) isn't a number.
- `NumberIndex` holds every numeric leaf of `analytics.json`, `backtest.json` and the data report, in 4 forms: v, |v|, 100v and 100|v|. It also holds the configured constants: MA windows, 5 bps, 60/40, the 3-year warm-up, $10,000, lookbacks, 50/30/20, plus window and team-size words.
- A number passes only if some stored value rounds to it **at the precision written**: tolerance ½·10^−decimals. So "9.1%" passes for 0.0912, and "9.15%" fails. Lookup is a binary search over the sorted values.

**Traceability by construction:** the Presentation Agent's `list_metrics` exposes **exactly** the fields the PDF tables print (`tabled_windows`, `momentum_view`). Any figure an agent can cite therefore appears in a code-generated table. `balance_and_traceability` checks this on the PDF text, and `test_every_citable_percentage_is_traceable_in_pdf` checks it on a fixture.

**Tests:** `test_guardrails.py` (supported, invented, precision, dates), red-team "invented return", "computed difference" and "hidden in precision", and benign look-alikes that must pass (rounding, magnitudes, parameters, years, dates).

**Limits:**
- It proves every number **exists** in the results, not that it's attached to the right claim. "Momentum's Sharpe was 0.71" passes if 0.71 is *any* Sharpe.
- Small integers can match by coincidence.
- Computed differences ("beat SPY by 3.7 points") are blocked unless the difference was itself computed.

Semantic misuse is left to the per-claim checks below and to visual review.

### G2. Compliance language (protects against H2)

**Where:** `BANNED_PATTERNS` in `guardrails.py`, used by slides, findings and team bios (tool time), `compliance_language` (eval) and the red-team.

**How:** regexes for:
- promises: guarantee, risk-free return, can't lose, no risk, will outperform/beat/deliver, certain to, proven to beat
- urgency: act now, don't miss, why … now, limited time
- overclaiming a rule: always picks/wins, never misses/underperforms

**Negation-aware guarantee rule:** "does not guarantee", "no guarantee" and "not a guaranteed hedge" are cautionary, so they're allowed. The negation must **directly** qualify the word: "Not only is it guaranteed" is still blocked. Disclosures need the negated forms, which is why this exists.

**Limits:** it's a pattern list. A novel phrasing can slip through. Visual review found "Why Consider It Now", and the pattern was added.

### G3. Balance: no cherry-picking (protects against H3)

**Where:** `adverse_windows()` (analytics) and `unacknowledged_adverse()` (presentation), at `build_pdf` time and in `balance_and_traceability` (eval).

**How:**
- Code lists every (window, benchmark, metric) where the MA strategy was worse than **SPY or 60/40** on drawdown, Sharpe or return.
- `build_pdf` refuses until **each** is acknowledged. The metric word **and** the benchmark must appear in the **same bullet**, and the window can come from that bullet or the slide title. A slide-level match was tried first and was gamed by accident: "60/40" in one bullet and "Sharpe" in another counted as acknowledged.
- Momentum lookback slides are excluded (`LOOKBACK_TITLE_RE`), because "12-Month Momentum" contains a 1Y synonym and its Cons are about momentum, not the MA strategy.
- For momentum: every lookback needs a Pro/Con slide whose `Con:` bullets cover each metric where that lookback trailed SPY (`momentum_adverse`).
- The Executive Summary must give a verdict on both strategies vs SPY.
- A comparison slide must cover momentum, MA, SPY and QQQ.

**Limits:** keyword-based. A bullet can mention the right words while understating the gap. Visual review checks tone.

### G4. Mechanism honesty for always-invested momentum, v3 (protects against H4)

v3 removed every cash rule, so momentum has **no defensive mechanism**. The visual review of the first v3 run found the deck still pitching it as "aimed at shallower drawdowns". Three checks were added, all in `momentum_section_problems` (at `build_pdf` time and in the `pros_cons_coverage` eval):

| Check | Rejects | Allows |
|---|---|---|
| `CASH_WORD_RE` (negation-aware) | "rotates to cash in downturns" on a momentum slide | "never holds cash", "no cash", "without moving to cash" |
| `DEFENSIVE_CLAIM_RE`, **per bullet** | "designed to limit drawdowns", "seeks to reduce losses", "the case for momentum rests on drawdown" in a bullet about momentum | Bullets about the MA strategy alone, which does have a drawdown aim. Observed outcomes ("its drawdown was 22.1%") |
| `NO_DEFENSE_RE` required in a `Con:` per lookback | A lookback slide with no Con saying it's always invested, with no defensive exit | — |

Code-owned text matches the rule. `rule_text(mcfg)` is the **single source** of the rule wording, used by the Backtest, Analytics and Presentation prompts, tool descriptions, the disclosures page, the Head to Head footnote and the allocation chart title. The `rule_disclosed_correctly` eval check fails if the disclosures say "always fully invested" for a cash-rules run, or omit it for a v3 run.

**Tests:**
- `test_no_cash_language_when_always_invested`: includes the exact live sentence that was falsely rejected.
- `test_always_invested_momentum_not_pitched_as_defensive`
- `test_momentum_section_requirements`
- `test_momentum_slides_cannot_acknowledge_ma_weaknesses`

### G5. Code-owned compliance content (protects against H5)

| Content | Owner | Agent can remove it? |
|---|---|---|
| "Hypothetical backtested performance…" footer: MA net of 5 bps costs, momentum excludes costs | `pdf.Deck`, on any slide with a chart or a number, and every table page | No |
| Important Disclosures page, always last: methodology, cost assumption, momentum rule via `rule_text`, fictional-team notice | `pdf.DISCLOSURES` | No |
| IN-SAMPLE label on the MA comparison and the tool output | `in_sample_comparison` page, `run_ma_backtest` | No |
| All metrics tables, the Head to Head, momentum detail, allocations, supporting data | Rendered from JSON by code | No |
| "YTD (through date)" on a partial final year | `_year_label` | No |
| Cost sensitivity (momentum CAGR at 5 bps per unit of turnover) | `momentum_view` | No |
| "AI-generated fictional persona" on each team card, and "(AI-generated, fictional)" in team page titles | Team renderer | No |

**Tests and evals:** `test_deck_has_disclosures_and_labels`, `test_performance_footer_is_true_for_both_strategies`, `test_every_code_page_has_its_title` (ReportLab had silently dropped a two-line title), `pdf_disclosures` (7 checks) and `team_quality`.

### G6. Fictional team integrity (protects against H6)

**Where:** `strategy/team.py` (a pydantic schema), at `submit_team` time. Bios are also checked by G2.

**How:**
- exactly 1 Portfolio Manager and 5 analysts, unique names, distinct focuses
- certifications from an allowlist: CFA, CAIA, FRM, CMT, CPA, CQF, PRM, CIPM
- employers checked against real firms by **word-boundary** match, so "Morgan Stanley" is rejected but "Citizens Ridge Partners" is allowed, even though "citi" is on the list
- names checked against famous finance figures
- `years_experience` must fit the career dates
- bio length bounds

Personas can't be named on agent slides (`persona_mentions`), only on the labeled team pages. Visual review once found a persona listed as the investor contact.

**Tests:** `test_team.py` (10), and red-team team and persona cases (11).

### G7. Backtest validity (protects against H7)

**Where:** the code design, not a runtime check: tested properties of `strategy/backtest.py` and `strategy/momentum.py`.

**How:**
- Signals use the close of day *t*, and weights apply from *t+1*.
- Walk-forward picks each year's MA using only earlier years.
- Momentum picks at month-end using only trailing returns, then drifts until the next rebalance.
- Agents can't pass arbitrary parameters: enums limit MA lengths and lookbacks, and slot weights and cash rules come from config.

**Tests:** shocking future prices must leave past weights unchanged (`test_no_look_ahead` in both backtest and momentum). Plus `momentum_reproducible` and the independent `crosscheck_momentum.py`, which doesn't import the project's momentum module.

### G8. Host-system guardrails from CLAUDE.md (protects against H8)

| Rule | Mechanism | Test |
|---|---|---|
| Never access files outside the project | `confine()` resolves every path, strips `\\?\`, and raises `ConfinementError` | `test_confine_rejects_outside_paths`, `test_confine_accepts_windows_extended_prefix`, red-team path cases (3) |
| No `import os` | pathlib, `secrets`, and `Path.replace` for atomic rename | `test_no_os_import_anywhere` scans every `.py` |
| No OS or system configuration access | No environment reads or writes in Python. Launchers set `MPLCONFIGDIR` / `PYTHONPYCACHEPREFIX` inside `.cache/`. | `test_matplotlib_cache_confined` |
| Never delete files | No deletion calls anywhere. Fresh run directories. Atomic writes. Docs refreshed by overwrite. | Code review, plus the rule in `tasks/lessons.md` |
| Agents can't modify anything outside the project | Agents have **no** file, shell or network tools. Their only side effects are the 21 tools in [tools-and-tokens.md](tools-and-tokens.md), all writing through `confine()`. | The tool catalog. Each agent's tool list is fixed in its `build()`. |

### G9. Cost and loop limits (protects against H9)

- Turn limits per agent: 20 by default, Team 8, Presentation 40.
- A run-wide 3M-token budget, checked before every model call (`BudgetExceeded`).
- `max_tokens` 16,000 per call.
- The `run_health` scorer fails runs over $15.

**Tests:** `test_turn_limit_and_budget` and `test_trace_and_cost`.

### G10. Data validation (protects against H10)

- The ticker allowlist is checked before any download (red-team: TSLA, BTC-USD).
- Start date between 1990 and today.
- `check_data_quality` must run before `save_dataset`.
- Today's incomplete session is dropped.
- Missing values before a ticker's inception aren't treated as errors.
- Moves over 25% are flagged (splits).
- At least 10 years of usable data.
- `validate_data` checks every momentum ETF has enough history for the 24-month lookback.

**Tests:** `test_data.py` and the `data_integrity` scorer.

## Lessons in guardrail design

| Lesson | Incident |
|---|---|
| **A false positive is as dangerous as a false negative.** It can strand the agent. | v3: "it never holds cash and has no defensive mechanism" (true) was rejected by a lookbehind regex that only exempted "never in cash". The agent couldn't satisfy the check and the run failed. Fixed with negation-within-the-window matching and a regression test using the exact sentence. |
| **Give agents a revise path.** | The same run: the agent had no way to fix a rejected slide except appending duplicates. `revise_slide` replaces a slide in place and passes the **same** `validated()` checks. |
| **Check at the unit the claim lives in.** | Slide-level keyword matching let unrelated bullets "acknowledge" a weakness. A slide-level defensive-claim check would have blocked true MA statements on a comparison slide. Both now check per bullet. |
| **Pattern exclusions drift with agent wording.** | "3-Month Momentum" was excluded, then the agent wrote "3-Month Lookback". The exclusion now matches both, with a test for each. |
| **One source for rule wording.** | Before `rule_text`, the prompts, disclosures and footnotes described the momentum rule separately and could disagree. |
| **Prove a new check fails on the known-bad artifact.** | Every new scorer and check was run against the run that exposed the problem before it was trusted. A layout test that "passed" was rewritten when it failed to catch the real defect. |
| **Code checks verify existence, not meaning.** | A real 0.4-point gap was claimed as a Pro, and a range misstated one endpoint. Each number was real. Visual review is a required layer. |
